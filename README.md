# tiktok-tts

Generate the funny TikTok lady voice (& more) from your browser. If you want to use the publicly available instance, you can [click here](https://tiktok-tts.weilbyte.dev). The voices are generated by TikTok; not affiliated with ByteDance LLC.

#### Configuration

There are some environment variables used for configuration:

| Variable      | Description        |
| ------------- |:-------------:|
| `ENABLE_METRICS` | Set to enable Prometheus metrics (port 3001) |
| `ENABLE_FRONTEND` | Set to enable, otherwise API only |
| `DATABASE_URL` | PostgreSQL database URL. **Required.** |
| `MAXIMUM_BODY_LIMIT` | Maximum accepted request body, in bytes (default 5000)|
| `REQUEST_LIMIT_HEADER` | Header to use for request size limiter. |
| `REQUEST_LIMIT_BYTES` | If request size limiter enabled, maximum bytes to accept (default 4000) |

##### Database
Upon connecting to a PostgreSQL database, migrations are run. Currently there is only one table containing TikTok session IDs. For the service to work, this table needs to contain at least one session ID with `is_active` set to true. The service caches this table in-memory and periodically fetches it.

Upon encountering invalid session IDs (as a result of it being expired or banned), they are removed from the in-memory cache and deactivated from the database.

##### Metrics
If `ENABLE_METRICS` is set, a Prometheus `/metrics` endpoint is exposed on port `3001`. This is useful for tracking total number of requests, faults, as well as estimated bandwidth usage. Keep in mind it does not support authentication.

##### Request size limit
A standard rate limit will not work as the requests are batched, so a 2000-word and 20-word request will both count as one. Instead, an optional request limiter is included, based on request size.

It is only active if the `REQUEST_LIMIT_HEADER` is set, which is the header which will be used to identify the originating IP address. You must use this behind a securely configured reverse proxy, otherwise the header can be spoofed. Requests without this header are rejected.

The request size limiting works by allowing the sender's request size to exceed `REQUEST_LIMIT_BYTES` once within a 60-second window, up to the `MAXIMUM_BODY_LIMIT`.

##### Building
Build it with Cargo, but in order for the front-end to successfully build, NodeJS modules `npx`, `tailwindcss` and `uglify-js` need to be installed (`npx` should be in PATH). Alternatively, you can build a container image using the included `Dockerfile`.

##### API documentation
```
GET /api/status
Description: Fetch the status of the API.
Responses:
    200: Service is available.
    Other: Service is not available; response text is error message.

POST /api/generate
Description: Generate TTS based on provided text and voice settings.
Request Body (JSON):
    text: The text to generate TTS for (less than 300 bytes for best quality; longer texts will be chunked and quality may degrade).
    voice: The TTS voice to use (e.g., `en_us_001`).
Responses:
    200: Returns an MP3 audio in binary format with `application/octet-stream` content type.
    400: User error encountered during TTS generation; response text is error message.
    429: You have hit a size limit! Re-send after UNIX timestamp in `Retry-After` header.
    500: Error encountered during TTS generation; response text is error message.
    503: Service not available; response text is error message.
```
